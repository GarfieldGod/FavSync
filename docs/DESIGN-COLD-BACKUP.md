# FavSync 冷备份与恢复

> 状态：**已实现并验收**（L1 小样全量恢复通过）。

**目标**：把总库的字节打成「加密、分桶、可增量、可核对」的离线副本，放进网盘或移动硬盘；
在任何一台装了本程序的机器上，凭桶文件 + 密码就能恢复回库里。

## 0. 五处必须修正的设计

| # | naive 方案 | 会出什么事 | 修正 |
|---|---|---|---|
| 1 | 桶 = 一次导出的产物 | 打包 20 小时、上传跨好几天，作业状态在内存里，重启即丢 | **桶是持久实体**（落库 + 状态机），作业只是执行器 |
| 2 | 按「视频」判断是否已冷备 | 同一视频可能有 64/80 两份画质，会漏掉「冷备过的是旧画质」 | 按 **backup 行**（`key + tag_norm + content_id`）对账 |
| 3 | 直接读库文件打包 | 库被手工动过/丢失，坏字节被封进冷备还标「已备份」= 假安全 | 打包前**账实核对**，不一致的条目踢出本次桶并报警 |
| 4 | 桶大小按「上传方便」定 | 桶大小实际是**恢复粒度**旋钮，定大了单条恢复要几小时 | 定稿 **2 GiB**，可改、不追溯老桶 |
| 5 | 靠本机 DB 知道「桶里有什么」 | 换台机器没有 DB；7z 目录在文件末尾，不下载完读不到 | 每批次一个**加密清单**，先下清单再决定下哪个桶 |

另有一条硬约束：**冷备份根必须在 `ArchiveRoot` 之外**，否则扫库会把恢复临时目录误认领进账。

## 1. 定稿参数

| 项 | 值 | 依据 |
|---|---|---|
| 桶大小 | **2 GiB**（2048 MiB） | 单桶恢复约 5.8 h；单文件 < 免费网盘 4 GB 上限；一批能一次传完 |
| 打包粒度 | 一次作业循环打多桶，可设 `maxGiB` | 断点在桶边界：取消只损失 1 桶 |
| 桶命名 | `<前缀>-<导出机>-<批次日期>-<序号>.7z` | 跨机不撞号、人眼可辨 |
| 密码 | 导出输一次、恢复输一次，**不落库** | 清单本身即校验器 |
| 冷备范围 | 只打 `backup` 行（**一个 key 只留一份字节，现在恒为 `role='primary'`**） | 早期 `version` 仓库已取消，不存在同 key 多份 |
| 7z | **自带 `tools/7z/7za.exe`**（不在 PATH 上找） | 与自带 `tools/adb/adb.exe` 同一套策略 |
| 面板位置 | 设置页最下方一张卡片，三层（配置 / 覆盖统计 + 三按钮 / 桶列表） | 不新开页面 |

## 2. 桶是持久实体

```
packing → packed → uploaded → pruned
   └──→ aborted（7z 失败 / 用户取消）
```

| 状态 | 含义 |
|---|---|
| `packing` | 正在打包。进程死在中途会停在这里；它和 `packed` 一起被算作「待上传」，所以中断的桶不会被误当成已完成 |
| `packed` | 本地桶文件已生成且**落账**（`cold_item` 已写） |
| `uploaded` | 云端已有一份（用户确认后手工标记） |
| `pruned` | 本地桶文件已删（仅云端保留；`cold_item` 不删——它描述的是云端事实） |
| `aborted` | 打包失败或被取消，桶号作废、条目退回未冷备 |

作业只是执行器：随时可以停、可以续，靠账（`cold_bucket` + `cold_item`）而不是内存状态决定「打到哪了」。

**桶号永不复用。** 取消的桶保留编号，条目退回未冷备。

## 3. 覆盖判定：按三元组对账，不按视频

「未冷备」= `backup` 行里存在、但 `cold_item` 里没有同三元组的行。

```
未冷备集合 = backup(role=primary) − cold_item(key, tag_norm, content_id)
```

不按视频判：同一视频的 1080P 打过桶、4K 没打过，按视频判会得出「已冷备」的错觉。

## 4. 打包前账实核对

库里说有、磁盘上没文件的条目**不能进桶**——否则坏账被封进「备份」，还标成已备份。

核对不通过的条目踢出本次桶，记进报告，不中断整批。

## 5. 清单（manifest）：方案的地基

7z 的目录索引在**文件末尾**，不下载完整个桶读不到内容。换台机器（没有 `catalog.db`）时
「预计能恢复出哪些视频」就无从谈起。所以每批次额外产出**一个很小的加密清单包**：

```
favsync-batch-<批次>.manifest.7z          -- 约 300~800 KB，-mhe=on
└ manifest.json
    { batch, createdAt, buckets:[{ id, file, bytes, sha256, items:[
        { key, avid, cid, title, tagNorm, quality, bytes, sha256, files:[...] } ] }] }
```

- 恢复端只下这一个文件 → 输入密码 → 立刻看到全部条目与桶号 → 挑条目 → 只下对应桶
- 清单里含标题，**必须加密**，不能为「方便预览」放明文
- 清单里的 `sha256` 与桶文件实际 sha256 对比，不一致 = 清单过期或被改
- 清单**必须与桶一起上传，且能从云端单独下到**。它丢了，桶就只是一堆无名二进制块

⚠️ 清单里的 md5/size 必须取 **`backup` 行**（桶里那份），不能取 `item.phone_*`（手机那份）。
outdated / 换源后两者不同，用手机值重算 `content_id` 会 join 不回 `cold_item` → 判「未冷备」→ 重复打包。

### 5.1 清单里带一份 `ledger`

恢复后新机的账目绝大多数能从磁盘自己长回来（`entry.json` 带元数据、`index.json` 带 size/md5）。
真正只存在于 `catalog.db`、丢了就算不出来的只有**探测结论**（gone / charge / exact / lower + TTL）——
重新逐条调 B 站 API 要几十分钟且会被风控。

`ledger` 段就是 `probe` 表的快照（压完约 80 KB）。导入规则：**只补缺、不覆盖**；
`expires_at` 已过期的结论直接丢弃。

## 6. 密码

**只在两个动作里存在：导出输一次、恢复输一次。** 不存数据库、不存 config（勾「记住」才走 DPAPI，标明仅本机本用户）。

**不自己造校验器——清单本身就是校验器。** `-mhe=on` 下错密码连文件名都列不出来、`7z l` 直接报错。
恢复向导第一步拿清单试列一次，错了立刻提示，不会白解一小时。

不做「恢复密钥 / 双密码」：7z 是单一密码，任何「另一把钥匙」都只是同一密码的副本，
写出来会让人误以为有托管。真实做法是导出结束强制勾「密码已单独保存」。

**密码丢了 = 数据变成一堆随机字节。** 这条提示常驻，不用轻量弹窗。

## 7. 恢复流程

```
选目录 → 读清单（1 个文件）→ 对账 → 选桶 → 入队下载/解密 → 校验 → 入库 → 报告
```

对账 UI 三类：**本机缺**（默认勾选）/ **已有**（跳过，可强制）/ **版本不同**（默认不勾，提示会并存为新版本）。

**四条铁律**

1. **恢复必须走 `RegisterBackup`**（与扫库同一条路），绝不写 `phone_*`、绝不改 `on_phone`。
2. **恢复目标是空库时，先 `UpsertLibraryItem`（`on_phone=0, state=synced`）再 `RegisterBackup`** ——
   后者只 `UPDATE` 不建行，顺序反了就是孤儿 backup 行。
3. **先解到临时目录，校验通过再 Move 进 `ArchiveRoot`**。临时目录必须在**总库同一个卷**上
   （`Directory.Move` 不能跨卷），位置是 `<库>/.favsync/restore-tmp/`（点开头，扫库跳过）。
4. **低档不进库**：搬之前先按档位判一次，避免「字节已 Move 进库、账上却没有 backup 行」的孤儿；
   `RegisterBackup` 返回 `Added=false` 时立即回滚刚搬的目录并计入失败。

### 7.1 空间预检三道闸

7z 是整桶解压，峰值 = 单桶解压体积，而临时目录就在库盘上：

1. 作业启动：`Σ待落盘字节 × 1.03 + 512 MB` 与库盘余量比，不够直接失败并报差多少
2. 每桶解包前再判一次，不够就整桶跳过（记 note，作业继续）
3. **一条都不用搬的桶完全不解读**；部分需要就用 `7z -i!` 只解那几个 `rel_dir`
   （靠 `-mx0 -ms=off` 本来就支持单条取出）

## 8. 目录与命名

```
<ColdRoot>/                       # 必须在 ArchiveRoot 之外
├── <前缀>-<机>-<批次>-<序号>.7z   # 桶
└── favsync-batch-<批次>.manifest.7z

<ArchiveRoot>/.favsync/restore-tmp/   # 恢复临时区（同卷，点开头，扫库跳过）
```

7z 参数：`-mx0 -ms=off -mhe=on`

| 参数 | 为什么 |
|---|---|
| `-mx0` | 视频已是压缩格式，再压只烧 CPU |
| `-ms=off` | 关固实，才能单条取出（部分恢复免整桶解压） |
| `-mhe=on` | 加密文件名。错密码列不出文件名 ⇒ **清单自身即校验器** |

## 10. 已知取舍

- **恢复后「仅在桶里」的条目要能看见**：`/cold/status` 的四组数字（未冷备 / 已冷备 / 仅在桶里 / 待上传）缺一组就会让人以为数据丢了
- **外来桶不冒充待上传**：`dir != 冷备目录` 的桶单列，不参与「待上传」统计
- **不自动删云端**：`pruned` 只删本地文件，且要求云端已有一份
